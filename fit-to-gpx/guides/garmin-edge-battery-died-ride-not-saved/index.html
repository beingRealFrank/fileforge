Your Garmin battery died mid-ride and the ride was not saved

You rode for hours, the battery ran flat, and the ride is not in Garmin Connect or on the device's history. Often the recording is still on the device as a file that was never closed properly. Here is how to find it, copy it off, and rescue the track.

Verified sample The sample below was produced by running this site's code on a synthetic FIT file cut short the way a flat battery cuts it. It has not been tested on every Garmin model.

Steps

  1. Charge the device, then connect it to your computer by USB. Garmin devices usually appear as a drive. Some users report the folder only shows up with the device switched off; if it does not appear, try that.
  2. Open the Activity folder. Forum users report that completed rides live in GARMIN\Activity and that a ride interrupted by a dead battery can be a file in GARMIN\TempFIT or a newest-dated file in Activity. Folder names can differ between models, so look for the newest .fit files by date. See, for example, this Garmin forum thread.
  3. Copy the file to your computer. Copy, do not move, so the original stays on the device.
  4. Drop the copy on the FIT repair tool. The Inspection box tells you in plain words what is wrong and how many position records can be recovered. Nothing is uploaded.
  5. Download the repaired .FIT or the GPX. The repaired .FIT keeps every complete record the device wrote (heart rate, power, laps). The GPX keeps position, time, elevation and heart rate.
  6. Import it. Use the import page of Garmin Connect or upload the file to Strava. If an app still refuses it, try the GPX instead.

Sample: what the inspection says for a cut-off ride

ride-truncated.fit (4,202 bytes)
  - The header promises 4,236 bytes of data but only 4,188 are there.
  - The file ends mid-record: 8 bytes after byte 4194 are an unfinished record.
  - The closing checksum is missing or wrong.
  - There is no session summary; repair adds a minimal one built from the recovered records.
  - 296 position records can be recovered.

Everything before the cut is intact; only the last unfinished record is lost. For a ride recorded once a second, that is typically the final second or so, not the ride.

When this will not work

  • If the device never created a file (for example the battery died before recording started), there is nothing to recover.
  • A file that is zero bytes has nothing in it. The tool says so instead of guessing.
  • Do not run a cleanup or format on the device before copying the files off.
